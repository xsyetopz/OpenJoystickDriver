## [0.6.0-alpha.1] - 2026-10-23

### Added

- A protocol description names what starts a controller's input (`inputStart`, with `PressGuide` for `SonySixaxis` over USB, because a USB DualShock 3 sends no input report until its PS button is pressed). Until such a controller sends its first input, its detail shows the input reason **Press the PS or home button**, `ojd controller show` gives `guide-not-pressed` (`GuideNotPressed` with `--json`), and `ojd controller list` tells you to press it, with `waits-for-guide-press` as the last `--plain` column and `waitsForGuidePress` with `--json`.
- `ojd diagnose --frames SECONDS` (1 to 15) tells you to keep the sticks moving, waits `SECONDS`, then asks the service once for the frames read in the last `SECONDS` seconds of its uptime clock and summarizes and lists only those, so the summary no longer spans the idle time before a sweep. `getFrameTimings` carries `lastSeconds`; the service refuses a value outside 1 to 15 as an invalid request, and the app and the support report ask for the whole window. The frame timing `summary` carries `lastSeconds` in `--json`, `--plain` (a column of the `window` row) and the support report, and only such a window measures `read-to-read` and stalls: the whole window holds the pauses before and after the input, and for a controller that reports only when an input changes, each pause counts as a stall, so the whole window has the stage gaps alone and the human output says that stalls need `--frames`.
- `ojd diagnose` summarizes the newest 15000 frames of each controller (15 seconds at 1000 Hz), not only the newest 8: frames, time span, and the median, 99th percentile and maximum of `read-to-parse`, `parse-to-dispatch`, `dispatch-to-delivery-virtual-device`, `dispatch-to-delivery-endpoint` and `read-to-read`, plus the count of stalls, the read intervals longer than 3 times the median read interval. The human output has one block per controller, `--plain` has `timing-summary` rows, and `--json` and the support report have `summary` in `cli-output.schema.json` and `report.schema.json`.
- `ojd config set KEY VALUE [--controller VVVV:PPPP]` and `ojd config unset KEY [--controller VVVV:PPPP]` write or remove one tuning key in your ControllerPatch of the model, or in `all.patch.json` without `--controller`, and refuse a value that a record refuses, such as a `stickDeadzone` that is not above 0 and below 1. The controller detail in the app has a **Stick deadzone** stepper that writes the same key through the service (`setControllerTuning`). The driver keeps no default deadzone, because XInput leaves it to the game; the wiki names the setting for a stick that rests off center.
- A controller that OJD serves while the system also lists it as a gamepad (`GCController.supportsHIDDevice`), such as a DualShock 3 over USB, shows **Also listed by the system** in its detail with a sentence to choose the virtual controller of OpenJoystickDriver in games. `ojd controller list` gives `alsoListedBySystem` with `--json`, a last `also-listed-by-system` column with `--plain` and the same sentence in the human output, and `ojd controller show` reports the duplicate exposure risk `SystemGameController`.
- A third virtual gamepad persona, `GameControllerCompatible` (`045E:0B13`, "Xbox Wireless Controller", transport `Bluetooth`, layout `XboxSeriesBluetooth`), sends the 17-byte Xbox Series Bluetooth input report 1 at the real controller's bit positions, which SDL's HIDAPI Xbox One Bluetooth driver and Firefox's `XboxSeriesXRemapper` read (four 16-bit sticks with the right stick on Z/Rz, Brake and Accelerator triggers of 10 bits, a hat that alone carries the D-pad, 15 buttons with Guide as button 13, and Share as Consumer `0xB2`), sends Guide again as System Main Menu on input report 2, where GameController reads Home, and takes rumble on output report 3, so Apple's GameController framework reads it; GameController binds `SDLCompatible` but reads no input from it. GameController names every control of it, Share included, and delivers Home only to the frontmost app. `./Scripts/ojd diagnose browsers --as game-controller-compatible` showed Firefox 158 and Safari 27.0.1 giving every control its standard slot but Share, and Chrome 156 every control but Guide, with Share as B17. Automatic selection never picks it: choose it with `ojd virtual set game-controller-compatible CONTROLLER` or in the app. It states `worksWithDefaultSDLHints: false`, so `ojd virtual show`, `virtual export-mapping` and `virtual launch` print the SDL-hints note for it, and `ojd virtual launch --sdl-gamecontroller-backend` makes SDL read it through GameController. The virtual-device, CLI-output and endpoint schemas list the persona. On macOS 27 with a Razer Wolverine Tournament Edition, a GameController game read A, B, X, Y, both bumpers and triggers, View, Menu, both stick clicks, the D-pad and both sticks; Guide and Share are verified only with `ojd virtual feed`.
- `./Scripts/ojd diagnose browsers [--as <persona>] [--browsers firefox,chrome,safari]` feeds one virtual gamepad through every control with `ojd virtual feed`, opens a Gamepad API page in Firefox, Chrome and Safari, and reports the standard-mapping slot and rumble result each browser gave each control. Output goes under `.build/browser-gamepad/`.
- The controller detail in the app has a collapsible **Tuning** group, closed by default, that lists each tuning key of the controller's record with its value and layer, as `ojd config show --controller` prints them.
- `OpenJoystickDriverGameControllerViewer` lists each GameController controller as a collapsible group with its controls in layout order and its other elements, and prints one JSON line per change.
- `./Scripts/ojd shots capture --menus` captures every main menu, the Activate Profile submenu and the status item menu (and its Profiles > Activate submenu) as screen rectangles, a parent menu with its open submenu in one image; `--all` includes them. Every pixel of a menu image outside the menu windows' bounds is transparent, so no other app shows beside a submenu or around the status item menu: `OJDRepositoryTool mask-image <png> <frame> <keep>...` masks the PNG in Swift, so `--menus` builds the Swift package before it opens a menu. Menus are found by AXIdentifier, so `--menus` alone needs no English UI; the app sets each main menu bar item, main menu item and status item entry's model id as its accessibility identifier. A capture refuses a menu already open, more or fewer menu windows than it opened, and a menu still moving or fading. Before each capture the route activates the app and raises the window through the Accessibility API, and waits up to `--front-timeout` seconds (default 5) for nothing to cover it; the refusal names that wait. The route refuses a second running copy of the app by its pids and reports a `pgrep` failure instead of calling the app not running.
- The localization checker fails when a translator comment does not name the specifiers of its value (`commentSpecifier`) or when a bundle's comment differs from the en-US comment of the key (`commentCopy`). The 15 protocol family names, the four long help descriptions of `ojd status`, `setting`, `controller show` and `record validate`, `ojd setting test-notification` and the Library sidebar title have comments that say what they name.
- `XboxXID`, `NintendoSwitchInputOnly` and `VendorFlydigi` hold their input layout in their descriptions (`defaults.input`), and the report-layout driver decodes it.
- `ojd setting test-notification` asks the service to announce a test notification to the app, which shows it and reports back; Send Test Notification in Settings takes the same path and shows the same results. The service answers a held `waitForServiceStatusChange`, or the next one to arrive within 3 seconds, with the event kind `testNotification` and an announcement identifier; the app answers with the new RPC method `reportTestNotificationResult` (`shown`, `denied` or `failed` with the system's reason), and `sendTestNotification` returns that outcome. The first app to take the announcement answers it. The service cancels a request that holds its reply open (`waitForServiceStatusChange`, and `sendTestNotification` while it waits) when its client closes the connection, so a closed or killed app leaves the held-wait count at once and never takes an announcement; a caller of `sendTestNotification` that leaves abandons the announcement. Every other request runs to completion even if its client has left. With no taker in 3 seconds, or no report in 30 seconds, the command fails with the new code `E2036` (exit 69); notifications that are not allowed fail with the new code `E2037` (exit 77); a failed delivery fails with `E2006`. A wait with no revision now answers as `firstRead`, and a cancelled wait as `holdElapsed`. Without `--timeout`, `ojd setting test-notification` waits `ServiceTimeouts.testNotification` (38 seconds: pickup, answer and the reply) instead of the 0.5 second request deadline. The app reports `failed` with the new text `ui.settings.notifications.noNotificationCenter` when it has no notification center or the system rejects the delivery, and shows `ui.settings.notifications.testReportLost` when the service no longer waits for its report, because the `ojd` request ended or its answer time ran out. The same text appears when asking for notification permission without a notification center. A held wait that is cancelled as it takes an announcement gives it back for the next wait within the 3 seconds, and once those have passed the announcement ends with `noAnswer` instead of reaching a wait that is already held. A `noAnswer` report is refused with the localized text `ui.settings.notifications.testReportNoAnswer`. The help of `ojd setting test-notification` takes its default `--timeout` from `ServiceTimeouts.testNotification`. A held request is answered with the connection-failure error when its wake pipe cannot be made, and a failed `poll` is reported. The Chinese texts of `error.E2037.message` now say that notifications are not allowed. The strings `error.E2036.message`, `error.E2037.message`, `ui.settings.notifications.noNotificationCenter`, `ui.settings.notifications.testReportLost`, `ui.settings.notifications.testReportNoAnswer` and `cli.setting.testNotification.abstract`, `.discussion` and `.success` need native review in every language but English.
- `OJDRepositoryTool`, a development executable that is not shipped in the app or `ojd` and depends only on `OpenJoystickDriverKit`, runs the Swift checks on files outside the bundle: `validate controllers <directory>`, `validate descriptions <directory>`, `validate profiles|virtual-devices <path>...` and `apply-patches --controllers <directory> --patches <directory> --out <directory>`. Each problem is one JSON line `{file, code, message}` and the exit status is 1 when there is one, and 64 for a call the tool refuses. The bundled catalog and descriptions load through the same checks.
- When the service's request listener ends on a fatal accept error, the service writes `<socket path>.failure.json` (`ServiceListenerFailure`, `service-listener-failure.schema.json`: `E2034`, the error number, the time, and the writing process with its start time) and keeps running. The app shows `E2034` with its text and the error number in its status line and problem banner at once, with a Restart listener action; a listener that starts, or an orderly quit, deletes the file. While the service cannot be reached, `ojd status` and `ojd diagnose` show the same instead of "service unavailable", only while the writing process runs; `ojd status` then exits with 69 (`E2034`). A file that cannot be used is reported as the new code `E2035` (`damagedListenerFailureRecord`, `ojd status` exits with 1). The strings `status.listenerFailure.detail`, `.earlier`, `.notRegularFile`, `.otherUser`, `.processCheckFailed`, `.tooLarge`, `.restart`, `.restartFailed`, `.restartFailedReason`, `.restartUnavailable`, `cli.status.group.listenerFailureLabel` and `error.E2035.message` need native review in every language but English.
- `ojd permission list` reports `PostEvent`: the Post Event access that remapped keyboard, pointer and scroll events need, with `requiredByActiveProfile` from the service. `--plain` adds a `required` or `not-required` column to that row. The status item, the problem banner and the Access area decide whether access is missing by the same rule (`AccessReadiness.hasMissingPermission`), so Grant Access shows only while a permission is missing. The View menu gains Show Toolbar and Hide Toolbar, the File menu Close and the Edit menu Delete; the Settings window keeps its toolbar. - `ojd setting reset [--force]` moves `Settings.json` to the Trash so every setting returns to its default. The app shows an alert when the settings file cannot be read, with Reset Settings, Show in Finder and Quit, and the Settings window offers Reset Settings and Show in Finder beside the error. While the file cannot be read, the menu bar item shows, and notifications, the launch update check and login registration do nothing instead of running on defaults.
- The settings file errors are localized and name `ojd setting reset`.
- A rumble template's optional `resendIntervalMilliseconds` takes effect: while any motor runs, the driver's keep-alive sends the last rumble report again, and a report with every motor at zero stops the resends. The XID, XUSB, report-layout, PS3 third-party, NVIDIA Shield and Switch 1 drivers get a keep-alive at that interval, also for a controller macOS serves. A Switch 1 resend carries a fresh output counter. The HID keep-alive now takes its writes inside the controller's output queue, after the tick's sleep, so a stop queued before the tick is not followed by a stale resend. A record or description that names the interval beside a mode's `session.keepAlive`, or in a family whose description declares a keep-alive (`vendor.gamesir`), is rejected by the schema, the Swift decoder and the Python validator. No bundled description sets the field.
- The endpoint accepts a `Drain` line after `FeedSession` and answers `Drained` once every `Frame` sent before it has played, the last one for its full `holdMilliseconds` (at least 8 ms), even when a send to the device is slow. A `Drain` before `FeedSession` or on a `Subscription` connection gets `E1010`, and one with a member besides `apiVersion` and `kind` gets `E1003`. The wait is not idle time, so the 2-second idle timeout counts from the end of the last frame's time, and a client that closes during the wait ends the feed. `Scripts/SDK/reference_client.py` sends `Drain` after its frames and waits for `Drained`; it has no play-time estimate. See the [endpoint protocol](docs/sdk/endpoint.md#drain).
- `ojd virtual launch --sdl-gamecontroller-backend` sets `SDL_JOYSTICK_MFI=1`, `SDL_JOYSTICK_ALLOW_BACKGROUND_EVENTS=1`, `SDL_JOYSTICK_IOKIT=0` and `SDL_JOYSTICK_HIDAPI=0` for the launched program only, so SDL reads controllers through Apple's GameController framework, the one SDL route that lists the `SdlCompatible` profile (`SDLLaunchEnvironment.gameControllerBackend`). It does not reset a profile choice, does not change the login session, and leaves out the `SDL_JOYSTICK_HIDAPI_XBOX*` and `SDL_JOYSTICK_HIDAPI_GIP` variables, which `SDL_JOYSTICK_HIDAPI=0` already covers.
- `ojd virtual launch [--] PROGRAM [ARGUMENTS...]` runs a program, an `.app` or a name on `PATH` with `SDL_GAMECONTROLLERCONFIG` set to the SDL mapping line of each profile that a connected controller serves (`SDLLaunchEnvironment`); a value already set stays first, and no other variable changes. The program keeps the standard streams, `--json` and `--plain` exit with code 64, Control-C and SIGTERM stop the program, and `ojd` exits with the program's status. No live virtual gamepad exits with `E2013` and starts nothing; a program that cannot start exits with the new code `E2033`. A test launches `/usr/bin/env` and reads the variable from the environment it prints. The ten `cli.virtual.launch.*` strings and `error.E2033.message` need native review in every language but English.
- Raw-USB records may list alternative modes, selected at USB detection, and a raw-USB mode's `session.usbStartup` overrides the record's raw-USB startup packets (a session names exactly one of `startup` and `usbStartup`). `interface` stays HID-only, because a raw-USB mode claims the interface its transport resolves. HID discovery reports no endpoints, because the IOKit registry publishes only the endpoint count; an `endpoints` key selects a mode on the raw USB scanner only, and a record whose HID mode names `endpoints` is refused. The schema, the decoder and the Python validator all require exactly one `default` mode, and the layout, template and capability conditionals apply to every mode, including in a record with one mode.
- Controller records hold a `modes` list, and each mode names its `protocol`: exactly one mode has the id `default` and no `match`, and every other mode needs a `match` of `link`, `interfaceSignature`, `manufacturer`, `product`, `bcdDevice`, and `probes` (probes are read last). A mode may also set `interface` and `session.startup`, which overrides `output.startup` while the mode runs. A patch that changes a protocol gives the whole `modes` array. The DualShock 3 record and the ShanWan DS3 clone (`2563:0523`) have a `bluetooth` mode that selects by link and sends the Bluetooth enable report, and pairing is documentation only. `interfaceSignature` also takes an `endpoints` set (each of `address`, `direction`, `transferType`, `maxPacketSize`) that must pair one-to-one with the interface's endpoints, and a model whose record runs a `receiver` or `dongle` variant reports the `proprietary-radio-receiver` link. A startup write's `transport` is `usb`, `bluetooth-classic`, or `bluetooth-le`; the decoder rejects `proprietary-radio-receiver`, as the schema does.
- `Resources/Schemas/crosswalk.schema.json` describes `Resources/Vocabulary/crosswalk.json` (`kind` `Crosswalk`): a source with document, version, URL and check date for each column, and a row per control id with a value or `null` per column. `./Scripts/ojd check schemas`, the Python tests and the Swift tests validate the file and reject a planted bad copy.
- `Resources/Vocabulary/crosswalk.json` records, per column, the document, version and revision it was confirmed against (`sources`), and explains single cells in `notes`. The wiki crosswalk table in [Control Names and Other Vocabularies](wiki/Controller-Records.md#control-names-and-other-vocabularies) is generated from it with `./Scripts/ojd vocabulary regenerate --write`, covers every control and the HID column, and `--check` runs in CI. Corrections: `TouchpadClick` is `BTN_LEFT` in evdev and `DualShockTouchpadButton` in Apple; the Apple paddles follow the Xbox Elite numbering (`RightPaddle1` is `XboxPaddleOne`, `LeftPaddle1` is `XboxPaddleThree`); `LeftTrigger` is Simulation Brake (197) and `RightTrigger` Accelerator (196); the D-pad ids list the D-pad usages 144 to 147 before the Hat Switch; `Back` lists Select (62) and AC Back (548), `Guide` lists AC Home (547) and `Capture` lists Record (178).
- The WebRTC bridge's `PeerMessage` button list is checked against `vocabulary.schema.json` by `PeerMessageTests.testTheFrameListsMatchTheSchemas`, which fails when the lists differ.
- `ojd virtual export-mapping [PROFILE] [--format sdl|w3c]` prints the SDL mapping (one line per profile, a valid mapping file) or the W3C Gamepad description of each virtual gamepad profile, and `ojd virtual show --json` gains `sdl` (`guid`, `mapping`) and `w3c` (`id`, `buttons`, `axes`) on each controller that has a live profile. Both are derived from the profile's report descriptor and report codec, not written per profile, in SDL's macOS IOKit order: every input report counts, buttons are the Button and Consumer pages and the Generic Desktop D-pad, Start, Select and System Main Menu usages, and axes include Slider, Dial, Wheel and the Simulation Rudder, Throttle, Accelerator and Brake, each ordered by usage; the `Generic` mapping equals the one in the equivalence snapshot. Each virtual device record states `worksWithDefaultSDLHints` (required in a definition, refused with `match`); `sdl.worksWithDefaultSDLHints` carries it in `--json`, and the human output of both commands notes a profile that does not work with SDL's default hints. The four `cli.virtual.export_mapping.*` strings and `cli.virtual.group.sdlHintsNote` need native review in every language but English.
- `./Scripts/ojd check tools` also runs `swift test` in `Tools/WebRTCBridge/`, and the CI job that runs it covers the bridge package. The route now needs the Swift toolchain and Xcode besides xmake and SDL3.
- The wiki has a [WebRTC bridge](wiki/WebRTC-Bridge.md) page: the two roles, the steps to connect two Macs, and each option of `ojd-webrtc-bridge`.
- `EndpointBridgeTests` runs the bridge's `HostBridge` against an in-process `EndpointServer` over its Unix socket: a granted feed reaches the virtual gamepad and stays open on `KeepAlive` lines, and a token without `control`, or an unknown token, gets `E1002` and no gamepad. The endpoint client and bridge logic moved to `Tools/BridgeCore/`, a package with no dependencies, so the root package takes it without any WebRTC code.
- `ojd diagnose --output` writes `data.frameTimings` into the support report: each connected controller's newest frames with the `Read`, `Parse`, `Dispatch`, `DeliveryVirtualDevice`, and `DeliveryEndpoint` stamps, as `ojd diagnose --json` lists them in `timings`. See [ojd diagnose](wiki/Command-Reference.md).
- Startup writes now come from the family's description. `output.startup` gains `phase`, `crc32Seed` (the Sony Bluetooth CRC-32 trailer with a seed) and an optional `delayMilliseconds`, a description's HID writes add `variants` and `when`, and a raw-USB format (`bytes`, `endpoint`, `timeoutMilliseconds`, `delayMilliseconds`, `sessionByte`, `toleratesRejection`) replaces the old rule that startup writes apply only to HID controllers. The GameSir heartbeat, the DualShock 4 Bluetooth report, the Switch 1 handshake and the Switch 2, Xbox 360 receiver and GIP startup packets moved out of Swift into `Resources/Protocols/`. A new `usbTransferTimeoutMs` key (`xbox.gip`, default 2000) sets the raw-USB transfer timeout.
- Keep-alive writes now come from the family's description. `defaults.session.keepAlive` holds the interval (`intervalMilliseconds`, the interval's only source: `keepAliveIntervalMs` is no longer a tuning key in records, patches, descriptions or the `controller show` output, and the schema, Swift and the Python validator reject it) and the fixed writes of each run, as HID reports or raw-USB packets limited with `variants`; `resendTuning: "lizardResendTicks"` sends the Steam Triton lizard-mode write every 75th run. The GameSir enhanced HID and G7 USB heartbeats, the GIP status packet, the Steam Deck lizard watchdog and the Steam Triton lizard-off report moved out of Swift; the bytes and intervals are unchanged, and `gameSirEnhancedHIDHeartbeatPayload` is gone.
- Switch 1 subcommands now come from the family's description. `defaults.session.subcommands` holds the subcommand report id, the rolling packet counter's modulus (shared with the rumble-only report) and the startup requests in order: the three mode subcommands and the two SPI motion-calibration reads (`spiRead` with address, length and purpose). The driver derives the pending reads and their reply matching from it, and the bytes, order and counter wrap are unchanged. The schema, Swift and the Python validator reject a missing or malformed list, a second read for one purpose, and subcommands on another family.
- The GIP named packets now come from the family's description. `defaults.session.namedPackets` of `xbox.gip` holds the `id`, `bytes` and `sessionByte` (always 2, the sequence number) of each packet a record can name in `protocol.initialization`, and a record naming an id the description lacks is rejected by the schema-backed validators in Swift and Python. The default startup of `xbox.gip` (`defaults.output.startup`) refers to those packets by `packet` id, and an id the description lacks is rejected. The Developer Tools pane has no diagnostic mode button.
- Six more `tuning` keys set what a family driver used to hard-code, each with its default in the family's `Resources/Protocols/<family>.json`: `lizardResendTicks` (`valve.steam-triton`), `usbCommandTimeoutMs` (`nintendo.switch2`, `vendor.gamesir`), `presenceResendReports` (`xbox.gip`, `xbox.xusb`), `adapterDisconnectDelayMs` (`sony.dualshock4`, `sony.dualsense`), and `usbStartupIntervalMs` and `usbStartupRetryDelayMs` (`xbox.gip`). The defaults equal the old built-in values. See [Adding or changing a controller record](wiki/Controller-Records.md).
- The endpoint accepts a `KeepAlive` line after `FeedSession`. It resets the 2-second idle timeout of the feed and changes nothing else, so a client with no new frame keeps its feed without repeating a frame. Outside a feed it is refused with `E1010`, and with a member besides `apiVersion` and `kind` with `E1003`. The WebRTC bridge host sends it every 0.5 seconds while no frame arrives, and drops peer messages that are over 64 KiB or are not a valid `Frame`. See the [endpoint protocol](docs/sdk/endpoint.md#keepalive).
- `Tools/WebRTCBridge/` is a separate Swift package, `ojd-webrtc-bridge`, that links LiveKitWebRTC and is a client of the SDK endpoint. On the Mac that runs the game (`--role host`) it turns frames from a WebRTC data channel into a virtual gamepad with a `FeedRequest` and sends each `RumbleCommand` back. On the player's Mac (`--role player`) it subscribes to a controller and sends its input over the data channel. The offer and the answer travel as one line each on stdout and stdin, and the bridge opens no listening socket. The app, the service and `ojd` do not link WebRTC. See [WebRTC Bridge](docs/sdk/webrtc-bridge.md).
- The new `frameQueueCapacity` tuning (1 to 1024, default 64, every family) bounds the queue of reports waiting for a virtual gamepad. It is set in `defaults.tuning` of each protocol description and overridden by a record, a `ControllerPatch`, or `all.patch.json`. See [Tune Timings and the Stick Deadzone](wiki/Controller-Records.md#tune-timings-and-the-stick-deadzone).
- `ojd record test VVVV:PPPP --packets CAPTURE --expect STATE` replays the received packets of an `ojd controller capture --json` file through a controller record's parser and compares the resulting state with an expected state. A mismatch lists the fields that differ and exits with code 1 and the new error `E2022`.
- `~/Library/Application Support/OpenJoystickDriver/Controllers/all.patch.json` sets a `tuning` default for every controller (a `ControllerPatch` with `selector.all`, `Resources/Schemas/controller-patch.schema.json`). A value takes the first layer that sets it: user record, `all.patch.json`, package, bundled record, driver default. `ojd config show [--controller VVVV:PPPP] [--json]` prints each effective value and the layer that set it. See the [command reference](wiki/Command-Reference.md#config).
- `ojd config show` without `--controller` marks each tuning key with the protocol families that read it (`families` in `--json`), taken from the controller records, and warns on stderr when `all.patch.json` sets a key that no connected controller reads. See the [command reference](wiki/Command-Reference.md#config).
- **BREAKING:** the `mod.json` lists are named after the document kinds: `records` is `controllers` (`Controller` files) and `patches` (`ControllerPatch` files), both in `Controllers/`, and `personas` is `virtualDevices`, with its files in the package folder `VirtualDevices/` (the folder `Personas/` is not part of a package). The user folder of virtual device files is `~/Library/Application Support/OpenJoystickDriver/VirtualDevices`, and the `OJDRepositoryTool` checks are `validate controllers` (for `validate records`), `validate virtual-devices` (for `validate personas`) and `apply-patches --controllers` (for `--records`). A `mod.json` with `records` or `personas` fails with `E4001` like any unknown key, and a `Controller` file listed under `patches`, or a `ControllerPatch` file under `controllers`, fails with `E4003`. A package or a folder with the earlier names is not read; move the files and rename the lists. `ojd status` lists a `Personas` folder beside `VirtualDevices` that holds files under `skippedVirtualDevices` with the folder to move its files to, and the `config-files` check of `ojd diagnose` and the app's Activity diagnostics warn about it.
- **BREAKING:** Every error has a stable code. The endpoint's error lines carry `E1001` to `E1008` in `code` instead of the old kebab-case names, and a refusal records `E1002`. The command line prints `error[E2xxx]: <message>` to stderr, remapping errors from the service carry `E3xxx` codes (the app shows them as a suffix, for example `(E3011)`), and [Error codes](wiki/Error-Codes.md) lists them all.
- `ojd explain CODE` prints what an error code means, its area, and its exit code or wire value. It works offline and ignores case. An unknown code is a usage error. See the [command reference](wiki/Command-Reference.md).
- Catalog the Microsoft Bluetooth Xbox controllers SDL lists (Xbox One S `045E:02E0`/`02FD`, Elite 2 `0B05`/`0B22`, Adaptive `0B0C`/`0B21`, and Series `0B13`/`0B20`) as `hid.descriptor`. ### Fixed

- A controller that has sent no input since its session started, such as a USB DualShock 3 before its PS button is pressed, shows the input state **Stale** (`Stale`) in place of **Waiting for neutral**, and its first input does not count as a recovery in `recoveryCount`. It had no input to return to neutral from.
- A raw-USB controller whose interface another process holds, such as a GameSir G7 SE `3537:1010` whose interface 0 another app opened, shows **Used by** that app and is served when the app lets go. macOS 27 refuses the open with `kIOReturnInternalError` as well as `kIOReturnExclusiveAccess`, so a failed open of an interface whose `UsbExclusiveOwner` names another process is read as held by it, in place of a device that OJD kept retrying as unavailable. OJD waits for the release that macOS announces, also while Bluetooth LE controllers are enabled, whose USB routing answered that wait as not supported, so the open was retried in a loop.
- A controller that another app holds publishes no virtual gamepad until the app lets go, and its detail shows **Not published (Another app is using it)** (`HeldByAnotherClient`) with no **Input** row. The virtual gamepad of a held raw-USB controller, such as a GameSir G7 SE that Steam holds, could send no input, so games listed a second pad that never moved.
- `ojd virtual show` lists the virtual gamepad choices as `virtual set` takes them (`sdl-compatible, generic, game-controller-compatible`) instead of their identifiers (`SDLCompatible`). The `--json` output keeps the identifiers.
- `just lint`, `just check` and the CI and release workflows run the pinned Biome that `Scripts/Quality/biome_binary.py` resolves, so they also pass in a linked worktree, which has no `node_modules` of its own; the recipe named `node_modules/.bin/biome` of the working directory. Outside a Git checkout the lookup fails with the `git` error; it used the folder itself as the main checkout.
- `./Scripts/ojd catalog regenerate` keeps the pinned upstream sources in `.build/catalog-sources` of the main checkout, so a linked worktree reads them from the network only when the main checkout has no copy.
- The pre-commit hook formats only the staged JSON files that `biome.json` includes, so a staged equivalence snapshot in `Tests/EquivalenceSnapshots/` keeps the `"key" : value` text that `./Scripts/ojd snapshots check` compares. The hook formatted its copy of the staged files outside the checkout, where the `files.includes` globs of `biome.json` did not match.
- `ojd diagnose` lists the `DeliveryVirtualDevice` time of each frame that a virtual gamepad publishes. The remapping router in front of the virtual gamepad dropped the delivery notice, so the timings stopped at `Dispatch`.
- The `Virtual gamepad` row of `ojd status` printed the backend's diagnostic text, such as `controller=LogicalControllerID(VID:0x3537 PID:0x1010 …) … last-attempted=88598501741541 … status=ended`, which named a controller whose session had ended and gave uptime nanoseconds. The row says `Off`, the error, or `On` with the names of the controllers that a virtual gamepad stands for. `--json` adds `virtualDevice.published`, and the diagnostic text stays in `virtualDevice.status`, `--plain` and `ojd diagnose`.
- `ojd controller show` named `System` as the server of a controller that the system cannot serve, such as a GameSir G7 SE over raw USB, while OJD served it. It reports `server` `OJD` with the `serverSource` `Route` for such a controller, as `cli-output.schema.json` lists.
- A raw-USB controller that another program holds, such as a GameSir G7 SE that Steam holds, shows `DeviceInUse` with the program's name, and OJD serves it once that program lets it go. The host answers the configuration read of such a controller with an exclusive-access error, which OJD read as a failed read five times and then left the controller as `ConfigurationUnreadable` until it was plugged in again.
- A DualShock 3 or Sixaxis that OpenJoystickDriver serves over USB releases its held buttons and sticks when it sends no input for a second, as a DualShock 4 does. A USB Sixaxis streams input while idle, so a second of silence means it stopped, such as on a hub that cannot power it. Without the timeout, the virtual gamepad kept the last pressed controls. `inputLivenessTimeoutMs` sets the time for the USB link.
- The mode-selection lines in the daemon log name the controller's location, such as `054C:0268 at location 0x00130000`, so two pads of one model, such as a DualShock 3 and its clone, can be told apart.
- A mode probe counts a stalled feature report as the controller's refusal also when macOS reports the stall as `kUSBHostReturnPipeStalled` (`0xE0005000`), as it does for a DualShock 3 clone's report `0xEF`. That code counted as no reply, so a probe that expects a stall never held and the log said the controller did not answer.
- A DualShock 3 or Sixaxis that OJD serves over USB lights its player LED: OJD writes the assigned slot after the controller's first input report, as it does for one macOS serves. Written right after the startup feature reads, the LED report was ignored, so the four LEDs kept blinking.
- Xbox One (GIP) controllers get rumble levels as percentages, `0` to `100`, as Microsoft's [MS-GIPUSB] Direct Motor Command and SDL's GIP driver define them; OJD sent `0` to `255`, so any strength above about 40% reached the motors at the same level. An acknowledgement of a fragmented GIP message counts the bytes received and the bytes still to come; the first fragment's acknowledgement counted the message's total length as received. Acknowledgements keep the reserved flag bit clear and carry the acknowledged message's own System flag, as SDL's `GIP_Acknowledge` does. Each GIP vendor message type has its own sequence counter. Only a virtual key frame with the Xbox button's key code `0x5B` presses Guide. A rumble report written to the `SDLCompatible` or `GameControllerCompatible` virtual gamepad enables each motor by its own bit (bit 0 right motor, 1 left motor, 2 right trigger, 3 left trigger); the bits were read in another order, which SDL's all-motors mask `0x0F` hid.
- Apps that read Apple's GameController framework, such as Safari, no longer list a "Xbox Wireless Controller" that never moves for each `SDLCompatible` pad. The framework bound `045E:02FD` and read nothing from its Xbox One GIP reports. `SDLCompatible` publishes `045E:0B0C`, the Xbox Adaptive Controller, which SDL reads with the same Xbox One driver and the framework does not bind on a virtual device. Use `GameControllerCompatible` for GameController apps.
- The virtual gamepad no longer adds a 15% stick deadzone to every controller that has no `tuning.stickDeadzone`: such sticks reach games and browsers as the controller reports them, so a game's own deadzone settings apply, and a drifting stick shows its drift. A record's `stickDeadzone` is radial, as documented: a stick reads zero while its deflection stays inside it, and a diagonal or a small cross-axis movement past it keeps both axes. It was applied to each axis on its own, which zeroed the smaller axis of a diagonal.
- **BREAKING:** An `XboxGIP` pad reports Share only when its record sets `shareButton`; every GIP pad read payload byte 14 as Share, also one whose record declared no Share. Linux xpad `MAP_SHARE_BUTTON` rows get `shareButton` `fromEnd` 18 (26 with `MAP_SHARE_OFFSET`), so 14 more bundled records declare Share, and the GameSir G7 SE (`3537:1010`) patch sets `fromEnd` 18 from a captured Share press. A pad with Share and no record parameter gets it from a patch; see [Select a Model With Protocol Parameters](wiki/Controller-Records.md#select-a-model-with-protocol-parameters).
- `ojd controller watch --output`, `ojd controller watch --all --output` and the endpoint read the virtual gamepad before the controller's input, so an `out` line or `output` field no longer shows a press before the input line that carries it, as a press between the two reads did.
- `ojd virtual reset` and Automatic in the app fail with the new code `overrideFileKept` and the file's path when the controller's persona file sets its own `identity` or comes from a package, instead of exiting 0 with the override still in effect; the file stays. `ojd virtual reset --all` and the app's settings reset fail with `cli.virtual.reset.allFailed` when such a file stays or the `VirtualDevices` folder cannot be read, and the service log names each kept file. The strings `ui.virtualProfile.failure.overrideFileKept` and `cli.virtual.reset.allFailed` need native review in every language but English.
- **BREAKING:** The `SDLCompatible` virtual gamepad (`045E:0B0C`) sends and takes the reports SDL's HIDAPI Xbox One driver reads, so Steam and other SDL 3 apps that list it as "Xbox Adaptive Controller" get input and send rumble. macOS 27 reports the transport of every `IOHIDUserDevice` as `Virtual`, which SDL does not read as Bluetooth, so SDL parses the reports as USB GIP packets: input is an 18-byte report with ID `0x20`, Guide is report `0x07`, and rumble is report `0x09` (12 bytes). The profile's transport is `USB`, its GUID bus is `03`, and a virtual device file's `layout` is `OJDGenericGamepad` or `XboxOneGIP`; `XboxOneSBluetooth` is rejected. The D-pad is four bits of the input report and both Y axes are complemented, so the SDL mapping binds them as `b11` to `b14` and `a1~`, `a4~`, and the JSON schema accepts `aN~` as a W3C axis source. Rumble report `0x03` is rejected. Steam read input and rumble on hardware with `045E:02FD`.
- OJD's exclusive claim on a HID controller (`ownership: exclusive`) took effect only on paper. It opened the device shared and then opened it again with the seize option; IOHIDFamily ignores a second open from the same client and returns success, so every seize "succeeded" with no seize (`ClientOptions=1`, other clients unaffected) and the controller showed `Exclusive`. The seize is now the first and only open of the device, a refused seize is closed and named (`OwnedByAnotherClient`, `AccessDenied` or `AcquisitionFailed`) before the shared open, and releasing, reacquiring and retrying a claim close the open before they open it again. Releasing a claim used to close the device and stop its input.
- A HID controller that another app seized before OJD admitted it stayed `Owned by another app` with no input after that app let go, until OJD restarted. macOS refuses the shared open too while another client seizes a device, so OJD had no open to retry from; it now retries the seize of every such device and starts its input once the seize holds.
- The kernel queue for a HID controller's input reports held 16384 bytes (`EnqueueErrorCount` rose to 604 on a DualShock 3). OJD sets `MaxReportBufferCount` and `ReportBufferEntrySize` on the open connection for 1,024 reports (fewer for a large report, at most 131072 bytes), and no longer reads the device's location property on every report. `ojd diagnose` has the check `hid-input-drops`, which warns with the controller and count for every device whose input reports the system dropped; the strings `cli.diagnose.group.hidInputDropsNone` and `cli.diagnose.group.hidInputDropsFound` need native review in every language but English.
- A raw-USB controller whose USB configuration descriptor cannot be read is no longer read again and logged on every 500 ms poll. When the host refuses the read (`accessDenied`) and reports an exclusive owner (`UsbExclusiveOwner`, such as Steam), the controller is left unclaimed with the new unbound reason `DeviceInUse`, logged once with the owner, and admitted again on the poll after the host reports no owner, with no re-plug. A refusal with no reported owner, and any other read failure after `usbConfigurationReadAttempts` (5) polls in a row, records the new reason `ConfigurationUnreadable` and waits for the controller to reconnect. The Controllers page and `ojd status` list the controller with the sentence of its reason; the HIDTool record probe refuses with `device-in-use` or `configuration-unreadable`. The strings `ui.controllers.deviceInUse` and `ui.controllers.configurationUnreadable` need native review in every language but English.
- The Activity log shows the service log when you open it. The window followed the log only for the area it was leaving, so opening **Activity** showed **No log entries.** and leaving it kept the log followed.
- A second app process, such as the app binary started from a terminal, no longer empties the session logs of the running app. The app holds a lock on `OpenJoystickDriver.log.lock` in the log folder; a process that cannot take it prints why on its terminal and leaves the logs alone.
- A PlayStation 3 controller that OpenJoystickDriver serves lights its player LED when it connects. Only raw-USB controllers got a player slot, so a Sixaxis over HID kept blinking until a game set its LED; it now takes the lowest free slot, as macOS-served controllers do.
- A HID controller's details show whether its startup output reached it (**succeeded** or **failed**), as a raw-USB controller's do, and the service log names the controller when a HID startup write fails. A failed write that the controller does not require, such as a Sixaxis player LED, left no trace before.
- The publication list of `ojd status` and `ojd diagnose` shows `status=ended` for a controller whose session ended, such as one you unplugged. It showed `status=none`, as if the controller were still waiting for its virtual device.
- **Served by** keeps the choice you click while the service applies it, and returns to the record's value only when the service refuses the change or does not confirm it within 2 seconds. It showed the previous choice again until the record changed, so the picker jumped back before it switched.
- **Set by** in a controller's details names the record layer as the Library does, such as **Your file**, instead of the command-line name `user`.
- The Advanced pane no longer repeats what **Enable Developer Tools** shows in a second row while the tools are off.
- `./Scripts/ojd notarize store-credentials` writes `NOTARIZE_APPLE_ID` and `NOTARIZE_KEYCHAIN_PROFILE` to `.env.release`; it stopped with an `ImportError` before.
- The Turkish text of `ojd binding set` after it stores a binding says that the source is assigned to the profile instead of that the profile sends it.
- A record that a patch changed keeps the text of its numbers: `ojd record show`, `ojd record show --json` and `ojd record draft` print `8E-2` and `1e3` where the patch file writes them, not `0.08` and `1000`, and an integer of more than 64 bits keeps its digits. The patch merge works on `OrderedJSON` values, keeps the member order of the record, and appends the members a patch adds in the patch's order; an array that a patch replaces has the patch's order.
- An endpoint client that the service refuses or closes with an error, such as `E1004` for a ninth connection, always reads that error line before the connection ends; a close that came while the service finished writing an earlier line could end the connection without it.
- The native-send deadline of a virtual gamepad, the 2-second wait for a virtual device to report cancellation, and the deadline of `withTimeout` in the command line now run on a timer thread of their own instead of `Task.sleep` on the cooperative pool, so a busy pool no longer delays them past their limit.
- The idle and hung-send deadline of a virtual feed, the frame-hold pacing of its player, and the timeouts of a virtual output transition now run on the same timer thread, so a busy pool no longer delays them.
- A virtual feed counts each frame's time from the moment its send returns, so a slow send no longer shortens the gap before the next frame below 8 ms, and its idle time starts at the end of the last frame's time instead of when the player task runs.
- Merge the stick reports that queue behind a slow virtual-gamepad publication to the newest state while keeping every button edge, so sticks no longer stutter. A remapping route's controller still gets every queued report, and ending a session drops held input. Not verified on hardware.
- List an Xbox One controller (`045E:02D1`) in `ojd controller list` while the XboxUSBDevice extension is active ([issue #18](https://github.com/xsyetopz/OpenJoystickDriver/issues/18)): the extension route reads the vendor, product, location, and name from the parent USB device. Not verified on hardware.
- Stop a USB pipeline that a detach stopped before admission started it from opening a session that nothing closed.
- Accept a report descriptor that ends with zero padding after its last End Collection, as the Xbox One S Bluetooth descriptors do. The HID descriptor contract previously rejected those controllers.
- The DragonRise generic USB PCB (`0079:0006`) no longer reads its face buttons one position off or its digital L2 and R2 as View and Menu. The descriptor fallback now uses the button order shared by SDL's two mappings for this ID, with Z and Rz as the right stick. Not hardware-verified.
- `./Scripts/ojd release bump-version` (`just release-bump-version`) no longer fails looking for README version patterns that were removed, and no longer requires a dated `CHANGELOG.md` heading, so the app `Info.plist` version can be bumped at the start of a cycle. The missing heading had left beta.5 development builds reporting `0.5.0-beta.4`.
- Restore prompt controller inventory updates, cancel stale HID initialization after removal, keep suspended controllers out of compatibility identity transitions, and preserve backend failure details when an identity change rolls back.
- Show why disconnecting, resuming, or wirelessly disconnecting a controller failed in that controller's details. The failure was recorded but never displayed.
- Explain a refused motion calibration in the user's language in `ojd controller calibrate` and the app: E3026–E3028 show their own explanation, and E3003 and an unavailable controller name the fix. The service's refusals previously reached both only as a generic or English service message.
- Release a Bluetooth controller's HID claim before disconnecting it, confirm the physical link closed, and restore the prior active session when disconnection fails or times out.
- Report typed HID, Bluetooth, and disconnect-stage failures instead of reducing them to generic Boolean or unavailable results.
- Restore the authenticated GitHub fallback when raw catalog source downloads are rate limited.
- Neutralize rumble and lighting before a sleeping or stopping controller's session closes, and keep a late output request from re-enabling them.
- Roll back only the output channels a failed write changed, so one controller's rejected write no longer undoes other outputs.
- Keep the wireless-disconnect timeout on time when Swift's shared thread pool is busy.
- Cut per-report CPU in output routing: eligibility checks describe only the reporting controller instead of every connected one, runtime identity tokens are computed once per controller, and remapping tracks the foreground app from activation notifications instead of querying it for each report.
- Publish virtual controller reports only when their state changes: the 8 ms idle keepalive is gone, and input the virtual profile cannot carry no longer republishes an identical report.
- Publish the virtual controller again after wake. A controller that returned with the same identifier as before sleep stayed without a virtual controller until it was reconnected.
- Watch for controllers through a new HID manager each time controller discovery starts, so discovery after wake no longer depends on the manager that sleep stopped.
- Reset a raw USB controller's port once when its startup write reports the device as disconnected, so the host enumerates it again as a replug does. A Razer Wolverine Tournament Edition (`1532:0A15`) that stayed attached through sleep failed every startup after wake until it was replugged.
- Open each physical HID controller once: a DualShock 4 no longer delivers every report twice, and OJD no longer opens its own virtual gamepads.
- Keep DualShock 4 input live: a duplicated report could hide its sensor timestamp advance, so OJD waited for a neutral report and dropped stick input and physical output.
- Quit within a second on SIGTERM or SIGINT instead of hanging in AppKit's termination loop.
- Send the full 49-byte DualShock 3 and Sixaxis output report so player LEDs change over USB.
- Start the menu-bar app without an app bundle instead of crashing on notification setup.
- Number GIP (Xbox One and Series) host messages as the Linux GIP driver does: system messages share one counter, security messages and vendor messages such as rumble each have their own, and no counter sends 0, because each starts at 1 and wraps from 255 to 1. Each command previously had its own counter that started at 0. Not hardware-verified.
