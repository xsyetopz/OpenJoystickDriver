# Test Microsoft Xbox One Controller (Model 1537)

For [OpenJoystickDriver issue #18][1]: USB device `1118:721` (`045E:02D1` in hexadecimal).

The record uses the GIP Xbox One parser, interrupt endpoints `0x81`/`0x01`, sets USB configuration 1 before it claims the interface, and uses the classic startup. Packets from the reporter's IOUSBHost test program confirm the GIP handshake, the player light, every input including Guide, and rumble.

That confirms the record and the protocol, and an owner reports the wired pad working on 0.6.0-alpha.3 after removing the driver extension, but OJD's USBDriverKit road is not confirmed. Checking the file needs no signing. The USB and lights-and-rumble checks need an installed, approved, provisioned OJD app and the `com.openjoystickdriver.XboxUSBDevice` extension.

[1]: https://github.com/xsyetopz/OpenJoystickDriver/issues/18

## Check the Bundled Record

```bash
just diagnose-record \
  Sources/OpenJoystickDriverKit/Resources/Controllers/045e/045e-02d1.plist \
  --validate-only
```

Expect:

```text
RECORD_VALIDATION result=valid
```

## Run the USBDriverKit Probe

1. Quit Steam, games, and utilities, and plug in with USB.
2. Run:

   ```bash
   just diagnose-record \
     Sources/OpenJoystickDriverKit/Resources/Controllers/045e/045e-02d1.plist \
     --seconds 45
   ```

3. Check that the controller stays on, `RECORD_HANDSHAKE` succeeds, and `USB_RX` packets arrive with no user-client, open-device, or transfer error.
4. Check the rest position, then press and let go of every button, D-pad direction, trigger, stick direction and click, and Guide.
5. Unplug and plug back in. Do the handshake and one control check again.

If the extension doesn't claim the interface, save `just diagnose-dext`. OJD never detaches the device as a fallback.

## Check Lights and Rumble With an Installed App

Make a test plan with the [physical-output steps](../physical-output.md) (`ojd` is the [command-line tool](../../../wiki/Command-Line.md)):

```bash
ojd controller list
ojd controller show 045E:02D1
```

Run each step on its own. Write down the player light and the planned left, right, and trigger rumble. The plan alone doesn't prove support.

Add to a new issue (the closed [issue #18][1] has the earlier reports): macOS version, Mac model, firmware if you know it, exact OJD and SwifterKit commits, installed extension identity and version, probe output, and results for opening, handshake, every control, reconnecting, the player light, and each motor it lists. Probe output can hold raw packets, so remove private parts before you post.

IOUSBHost packets back up the record's values. They don't test OJD's generated USBDriverKit extension and its app wrapper, which still need this retest.
