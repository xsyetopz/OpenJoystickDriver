# Experimental Controller Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Update this file after each implementation slice by changing the relevant checkbox, adding the exact command output summary, and linking any new local source evidence.

**Goal:** Add experimental input support for Steam Controller, DualShock 3, DualSense, Switch Pro, and standalone Xbox Adaptive Joystick while preserving honest documentation that physical hardware validation is still required.

**Architecture:** Add protocol-specific parsers and profile metadata behind the existing `ParserRegistry -> DeviceCatalog -> InputParser -> ControllerEvent` pipeline. Keep quirks and experimental status in schemas/profiles where the current architecture can represent them, and add parser code only where the source protocol requires report decoding or handshakes. Treat app-facing output as the existing Xbox One S compatibility profile unless a later hardware test proves a different virtual identity is required.

**Tech Stack:** Swift 6 package, macOS 14-compatible Swift executable parser harnesses for focused parser regressions, Swift Testing files retained for repository test coverage where the local toolchain can compile them, JSON controller profiles, JSON schema validation through `./scripts/ojd validate profiles`, Linux HID driver source evidence, DriverKit/user-space HID output paths already present in OJD.
