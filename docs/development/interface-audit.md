# Interface audit: 0.6.0-alpha.2

Each window, sheet, menu, and control of the app, read on 2026-11-11 from the installed 0.6.0-alpha.2 (build 1.21.99) on macOS 27.2 and from the source of this branch.

## Interface level of each control

Each control in sections 1 to 7 has a Level and a Level basis. Simple shows the controller list, each controller's state and next step, the profile choice, Test Input, and the permission steps; Advanced adds the virtual gamepad kind, who serves a controller, tuning, identifiers, records and patches, and the activity log; Developer is a tool that shows only in Advanced with the developer switch on (packet streams, raw reports, contributor diagnostics). A window, menu, or toolbar that holds a Simple row, or is needed to reach one, is Simple. The rule left 64 controls undecided. The maintainer answered three questions: W07 is Simple, alerts show in both levels, and the rest is decided by the software and Apple practice. On confirming the list, the maintainer moved creating and editing a profile and prerelease updates to Simple, and the Access area's programs, tokens, endpoint and port under the developer switch; those rows end "(confirmation popup)". Each of the other rows names its evidence and ends "(decided by evidence)".

The file holds 130 distinct controls (W01-W11, S01-S24, M01-M17, T01-T21, C01-C32, P01-P18, I01-I07). The sheet-width comparison table repeats S01-S24 with the same level, which makes 151 table rows.

| Level | Controls |

Rows that one level holds only in part, with the part in the other level named in the basis: C06 (identifiers and route are Advanced), C24 (endpoint and lists are Developer), M08 and M17 (Activity Log and Explain Error Code are Advanced). The app hides those parts row by row.

## How to read it

- **Source** is a path under `Sources/OpenJoystickDriverPresentation/`. The line is omitted; the file is the unit.
- **Measured** is a size in points (width x height) from the Accessibility reading of the installed app ("A" with its section number). "not measured" says the element was not open or was not read through Accessibility; the source size follows when the source states one.
- **Screenshots** are the captures of the installed app, each named `ojd-alpha2/<file>.png`. A reading of Apple's apps is "R" with its section number.
- **Guideline** is a page of the Human Interface Guidelines.
- **Reference** is the app the element was compared with: Notes and System Settings (R1 to R3), or an open-source app.
- **Decision** is `fix` or `keep` with its reason.
- Nothing here is a reproduction; the findings under "Controls that can appear to do nothing" still need one per control.

## Findings seen in the baseline

1. The Controllers list header reads "0 controllers connected" above a listed device (`ojd-alpha2/main-Controllers-baseline-0-connected.png`). The count is `deviceCountLabel` (`MainWindow/MainWindowSummary.swift`); the list also holds the devices OJD does not serve (`Controllers/Inventory/ControllersView.swift`). In the later reading the same header read "1 controller connected" above two rows (`ojd-alpha2/main-Controllers.png`).
2. That device shows the raw identifier `2dc8:301c` and the word "USB" as its row title (`Controllers/Inventory/ControllersView.swift`, `"\(unserved.identity)  \(unserved.connection)"`). `inclusion`: "Avoid using specialized or technical terms without defining them."

Both are rows C03 and C04 below.

## Findings without a planned fix

- The header count and the identifier above (C03, C04). The header and toolbar title should count the rows the list shows, or say "1 controller, 1 device not served"; a device OJD does not serve should be named by its model when the catalog knows it.
- Heights below the 20 pt minimum of `accessibility`: the two disclosure labels "Tuning" (75 x 16) and "Advanced" (94 x 16) in the controller detail (A2); the arrow buttons of the stick dead zone stepper are 20 x 12 inside a 20 x 24 stepper. Switches (36 x 16) and the window's traffic lights (16 x 16) are system controls and stay. The smallest intended hit areas are 28 x 28; the readings show these smaller ones.
- Unnamed controls: three push buttons of the controller detail, the Create a token sheet's two checkboxes and two buttons, and the New profile sheet's checkbox and two buttons have no name or description in Accessibility (A2, A7).
- Toolbar heights differ by window: main window 52 (Notes 52), Settings 56, Input Test 66 because its Refresh button shows a text label below the icon (A1, A4, A5).
- The word "Advanced" names three things: the Settings pane, a disclosure in the controller detail, and the interface level. The pane and the disclosure need a different word, or the level does.

Differences and decisions:

- The extras are Control Center panels with 32 pt rows and a switch in the title. OJD's item is an `NSMenu` with 24 pt rows. Keep: `the-menu-bar` asks for a menu, not a popover, and the panels are Apple's own Control Center surface.
- Each extra ends with a row that opens its settings page. OJD's "Settings..." matches: keep.
- X2 shows each device's battery percent in its row. OJD's 2C row shows no battery over Bluetooth LE, while X2 shows 83% for the same pad. The 2C's Bluetooth LE battery byte reads 0, so OJD has no value to show.
- X2 and X3 list devices at the top level with no submenu. OJD lists each controller at the top level with a one-level submenu for its profile and actions. Keep: `menus` allows one submenu level, and the actions do not fit one row.

## Keyboard and VoiceOver

Run on 2026-11-13 against the installed app, build `8456f9de8665`, macOS 27.2, through the Accessibility API (a small Swift reader of `AXRole`, `AXTitle`, `AXDescription`, `AXHelp`, `AXEnabled`, `AXFocused`, `AXTitleUIElement`; scratch only). **VoiceOver itself cannot be driven here**, so the result rests on the Accessibility names: a control counts as named when `AXTitle`, `AXDescription`, or the text its `AXTitleUIElement` points to is not empty. The Settings switches have an empty `AXTitle` and `AXDescription` and are named through `AXTitleUIElement` (their row's text), which VoiceOver reads. An element left unnamed was counted a gap only for a button, menu button, pop-up, segment, checkbox, slider, text field, or image. The window's close, minimize and zoom buttons and the scroll bar parts are system chrome with no title and are not counted.

`AppleKeyboardUIMode` was 0 (Tab reaches text fields and lists only). It was set to 2 for the run, the app was quit and reopened so it took effect, and it was set back to 0 afterwards. The synthetic Tab (key code 48) was posted with `CGEvent.postToPid` and read back through `AXFocusedUIElement`.
